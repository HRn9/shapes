# Паттерны Bridge и Visitor - Реализация

## Обзор

В данном проекте реализованы два важных поведенческих паттерна проектирования:

- **Bridge (Мост)** - разделяет абстракцию и реализацию, позволяя изменять их независимо
- **Visitor (Посетитель)** - позволяет добавлять новые операции к объектам без изменения их классов

## Паттерн Bridge

### Назначение
Паттерн Bridge позволяет изменять реализацию отображения геометрических фигур без изменения кода самих фигур.

### Структура

```
Renderer (интерфейс)
├── ScreenRenderer (конкретная реализация для экрана)
└── PrinterRenderer (конкретная реализация для принтера)

ShapeRenderer (абстракция)
└── Связывает фигуры с рендерерами
```

### Преимущества
- **Гибкость**: Можно легко добавлять новые устройства отображения
- **Независимость**: Изменение рендерера не требует изменения фигур
- **Расширяемость**: Легко добавлять новые типы рендереров

### Пример использования

```typescript
// Создаем рендереры для разных устройств
const screenRenderer = new ScreenRenderer();
const printerRenderer = new PrinterRenderer();

// Создаем рендерер фигур
const shapeRenderer = new ShapeRenderer(screenRenderer);

// Отображаем фигуры на экране
shapeRenderer.renderShapes([oval, tetrahedron]);

// Меняем рендерер на принтер
shapeRenderer.setRenderer(printerRenderer);
shapeRenderer.renderShapes([oval, tetrahedron]);
```

## Паттерн Visitor

### Назначение
Паттерн Visitor позволяет добавлять новые операции к геометрическим фигурам без изменения их классов.

### Структура

```
Visitor (интерфейс)
├── AreaVisitor (визитор для вычисления площади)
└── PerimeterVisitor (визитор для вычисления периметра)

Shape (абстрактный класс)
├── Oval (конкретная фигура)
└── Tetrahedron (конкретная фигура)
```

### Преимущества
- **Расширяемость**: Легко добавлять новые операции над фигурами
- **Инкапсуляция**: Операции инкапсулированы в отдельных классах
- **Чистота**: Классы фигур не загрязняются кодом операций

### Пример использования

```typescript
// Создаем визиторы для вычислений
const areaVisitor = new AreaVisitor();
const perimeterVisitor = new PerimeterVisitor();

// Вычисляем площадь всех фигур
for (const shape of shapes) {
  shape.accept(areaVisitor);
}
console.log(`Общая площадь: ${areaVisitor.getTotalArea()}`);

// Вычисляем периметр всех фигур
for (const shape of shapes) {
  shape.accept(perimeterVisitor);
}
console.log(`Общий периметр: ${perimeterVisitor.getTotalPerimeter()}`);
```

## Интеграция паттернов

Оба паттерна могут использоваться совместно для создания гибкой системы обработки геометрических фигур:

```typescript
// Используем Bridge для отображения
shapeRenderer.renderShapes(shapes);

// Используем Visitor для вычислений
for (const shape of shapes) {
  shape.accept(areaVisitor);
  shape.accept(perimeterVisitor);
}
```

## Архитектурные решения

### Bridge Pattern
- **Абстракция**: `ShapeRenderer` - управляет отображением фигур
- **Реализация**: `Renderer` интерфейс и его реализации
- **Выгода**: Разделение ответственности между отображением и фигурами

### Visitor Pattern
- **Визитор**: `Visitor` интерфейс и конкретные визиторы
- **Элемент**: `Shape` с методом `accept()`
- **Выгода**: Легкое добавление новых операций без изменения фигур

## Заключение

Реализация паттернов Bridge и Visitor демонстрирует:

1. **Гибкость архитектуры** - легкое добавление новых устройств и операций
2. **Разделение ответственности** - каждый класс имеет четкую задачу
3. **Расширяемость** - система легко масштабируется без изменения существующего кода
4. **Поддерживаемость** - код легко понимать и поддерживать

Эти паттерны особенно полезны в системах, где требуется гибкость в реализации и расширении функциональности.
